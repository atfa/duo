Why two agents

An agent reviewing itself is still one perspective.

A single agent can write the code and approve it in the same context. Duo makes review structurally independent: two sessions, two worktrees, one commit both sides can inspect.

Austin · implementer

Builds in its own worktree.

Works on its own branch and checkout. Implements the agreed task, commits in reviewable increments, and reports the evidence Duo needs to verify it.

  • own branch and worktree
  • commits with exact SHAs
  • tests and build output attached
Tony · independent verifier

Verifies the exact commit.

Reads the real diff in a separate checkout. In Goal and Step, Tony also co-designs the plan and cross-reviews the implementation before signing the gate.

  • independent checkout
  • reads the real diff
  • signature bound to a SHA

Peer, not subagent. Tony has his own context and his own worktree. He cannot rubber-stamp a summary, and Austin does not edit Tony's checkout.

How it lands

Four checkpoints between an idea and your branch.

Each checkpoint is backed by Git, not by a chat message. If the evidence stops matching, the gate closes.

01 / ISOLATE

Two worktrees, two branches.

Each agent works in its own checkout under the session directory. Parallel edits become an explicit merge, never a silent overwrite.

worktrees/20261022-211328/austin · worktrees/20261022-211328/tony
02 / COORDINATE

A plan both agents signed.

In Goal and Step, work starts only after both approve the same plan or step-queue version. Any edit creates a new version and resets both signatures.

plan v4 austin ✓ tony ✓ · any edit resets both
03 / VERIFY + SIGN

Approval covers a commit, not a vibe.

Verification reads the real diff and runs the checks. A signature binds to the SHA that was reviewed; if the branch moves, the old approval no longer counts.

austin 6f2a1c9 · tony signed 6f2a1c9 ✓
branch moved → signature revoked
04 / DELIVER

Move only when it is provably safe.

Delivery is read-only until the final fast-forward. When it needs to move your branch, Duo refuses if the repository is dirty or the move is not a fast-forward — and changes nothing.

deliver main ← verified HEAD (fast-forward only)
dirty tree → refuse, checkout untouched

v0.14.4 · Remote control

Steer the session from your phone.

Type /qrcode and scan it. The phone becomes a console for the running session — both agents live, the next task, pause and continue, a mode, driver or model switch, a fresh session, the observer's report — while the work keeps running on your machine.

01 / PAIR

One QR code, eight hours.

/qrcode mints a room and a secret. The secret rides in the URL fragment, which a browser never sends, so the relay never sees it. A pairing expires after 8 hours, /remote off revokes it immediately, /qrcode new rotates it, and a new session reconnects by itself.

02 / CONTROL

The same workflow, from a phone.

A task sent from the phone enters through the same SubmitTask a keystroke uses, so phases, gates and delivery behave exactly as they do at the terminal. Pause or continue the round, switch fast, step or goal, pick a driver or model, start a fresh session or ask for a report — without walking back to the desk.

03 / RELAY

Ciphertext in the middle.

The default relay is a Cloudflare Worker that stores encrypted envelopes only: it can drop or delay traffic, but it cannot read a prompt or forge a command. Self-host it from remote/ and point remote.url at your own worker.

Quick start

Two commands to a second opinion.

Install the binary, run it inside any Git repository, and describe the task. Duo handles the worktrees, the gates and the delivery.

01

Install

macOS or Linux, amd64 or arm64. Or build from source with Go 1.24+.

curl -fsSL https://raw.githubusercontent.com/atfa/duo/main/scripts/install-release.sh | bash ./scripts/install.sh

The release archive carries v0.14.4, remote control included.

02

Run inside your repo

Fast is the default. Escalate when the work needs a negotiated plan or an ordered queue.

duo duo --mode goal duo --mode step
03

Review and push

Duo delivers the verified result to the branch you started from. Inspect the commits, run your own tests, push when you are happy.

FAQ

The questions engineers ask first.

Isn't this just subagents?

No. A subagent shares its parent's session and working tree. Duo runs two independent agent sessions with separate worktrees and branches, and their approvals are bound to the commits they actually reviewed.

Do I need two models or two API keys?

No. Use the same driver for both agents, or choose per agent with --austin-driver and --tony-driver. The built-in drivers are pi, agy, opencode and codex.

What happens when both agents edit the same file?

Each edit lands in its own branch, so the result is a normal Git conflict at integration — visible and resolvable. Duo does not discard uncommitted work to force a merge.

What if verification fails?

The gate stays closed. Tony reports the issue against that commit, Austin fixes it in his worktree, and a new commit needs a new verification. The old signature does not carry over.

Does Duo rewrite my history?

No. Delivery only fast-forwards the branch you started from. If it cannot be fast-forwarded, or moving it would overwrite uncommitted changes, Duo refuses and leaves the checkout untouched.

Does my code leave my machine?

Duo is a local Go binary: coordination, worktrees and evidence stay on your machine, and prompts go to your agent provider exactly as they would without Duo. Pairing a phone adds an optional relay that carries encrypted envelopes only — it never sees a prompt or the pairing secret, and a machine with no pairing sends it nothing.

Is it open source?

Yes, MIT licensed. Source, issues and releases live at github.com/atfa/duo.
